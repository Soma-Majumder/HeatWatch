3 · Who decides

If the model ignores the prompt, code still holds

Every important rule lives in two places: the prompt asks for it, and the runtime enforces it. Pick a mistake to see what catches it.

The model decides

  • Which tool to call next, with which grouping
  • How to read "this winter" (then checked)
  • Whether a finding is worth following
  • When the evidence is enough
  • How to word the briefing

The runtime guarantees

  • Only allowed tools run, with valid arguments
  • No comparison before coverage passes
  • Budgets, timeouts and cancel always win
  • Every number in the briefing matches the ledger
  • No causal wording, no addresses in the text

4 · Tools

Eight tools, all read-only

Five tools fetch data and three control the run. Click a card for its contract. Every data tool returns numbers computed in code, plus a required reason for the trace.

A tool call and the decision after it

compare_periods(area = Brooklyn, group_by = council_district,
                period_a = 2025-10-01..2026-01-15, period_b = 2026-10-01..2027-01-15,
                reason = "Is it up, and where?")
→ ledger #2: 14,200 → 18,400 (+29.6%); top 2 of 16 districts hold 69% of the change

The tool computed the 69%, so the model only compares it with the skill's rule (two-thirds or more in a quarter of the districts or fewer). The rule is met, so the next call is count_buildings, not a weather check. Illustrative numbers.

The first skill

skills/heat-investigation/
  SKILL.md
  references/heat-season.md
  references/branching.md
---
name: heat-investigation
description: Method for investigating questions
  about NYC heat complaints: whether they rose,
  where, and whether buildings or weather explain
  it. Use for any comparison of periods or places.
---
1. Fix scope: area and exact dates
2. check_coverage first; a gap means stop
3. compare_periods, then ONE next step:
   concentrated → buildings · even → weather
   small or down → answer directly
4. Rule out weather before concluding
5. Stop when every claim has a ledger id

What is not in v1, and why

Memory
Nothing about users is remembered. Add a profile only if one person keeps clarifying the same district.
Vector search
The data is structured and queried exactly. There is no document pile to search.
Subagents
At most 8 queries against one source. Splitting the work would split the evidence.
Planner
The skill is the plan. Add a planning step only if wrong first moves show up in 20% or more of failures.

    7 · Evals

    Test the path, not just the answer

    Each case runs 5 times on recorded data, so only the model varies. Safety cases must pass all 5. Click a row for its expected path.

    CaseKindQuestion or setupExpected endPass rule

    What gets graded

    Outcome
    Status, numbers, finding types, no forbidden wording. Graded by code.
    Path
    Coverage first, required tools used, right skill loaded, recovery after errors, stopping within budget. Graded by code.
    Wording
    Faithful and clear. A model grader, trusted only after 90% agreement with 30 human labels, never alone on safety.

    The gate for every change

    Baseline
    The agent must beat the fixed pipeline on concentration and weather cases, and never do worse on safety.
    Blocked if
    Any safety case drops below 5 of 5, the score falls more than 3 points, or median steps rise by more than 2.
    Failures
    Each one is tagged by layer, fixed, then added as a new case.

    8 · Safety

    The real risk is blaming the wrong building

    HeatWatch cannot take an action, so its controls focus on what reaches the briefing and on a full trace of every run.

    Smallest version first, then let failures decide

    MVP is accepted when

      Where a failure comes from

      Check in this order, cheapest first.

      1. Harness: a check passed something it should have failed
      2. Tool: correct call, misleading result
      3. Context: the needed fact was not in front of the model
      4. Skill: not loaded, or its rule is wrong
      5. Instructions: present and clear, but another rule won
      6. Model: all of the above fine, still fails 2 of 5; a stronger model passes
